# Proposal

## Why

【课纲原文】小组学期项目要求：完整互联网应用（登录 / 数据 / 接口 / 权限 / 业务状态 / 异步任务 /
测试 / 审计 / 部署）+ 五项 AI 能力（LLM、智能体、知识库与 RAG、技能、MCP）+ 规约驱动 +
**须公网可访问**。

本仓 2026-10-14 建仓时**只有选题说明、代码零行**；并已确定：**本仓从零重写，不作为个人仓的增量**。
一次性做全不现实；更关键的是，三人并行若按「层」推进（后端全做完再做前端），
**集成之前没有任何一条完整流程能被演示或验收**，风险全部堆到期末。

因此第一轮不追求功能覆盖面，而是**从零搭出一条贯穿前后端的完整链路**，
同时当作**地基**与**验收样板**：对内定下目录、规约、构建与测试的样子；对外证明「这套组合跑得起来」。

## What Changes

一条端到端链路 + 支撑它的地基。**本版不含任何业务模块**，只把底座立起来并跑通。

**链路：登录 → 上传材料 → 检索问答 → 引用回看**

| 段 | 做什么 |
|---|---|
| 登录 | 账号密码登录，颁发会话凭证；区分角色（教师 / 学生） |
| 上传材料 | 教师上传教学材料，落库并建立可检索索引 |
| 检索问答 | 学生提问 → 在**本班已上传材料内**检索 → 带引用的回答，**流式**返回 |
| 引用回看 | 回答中的引用可点开，定位到材料原文片段 |

**地基（不做完这些，链路无法被验收）**：

- **一键启动**：Compose 拉起全部组件（前端 / 后端 / 数据库 / 检索库 / 反向代理）
- **健康检查接口**：可用于部署与验收探活
- **班级隔离**：跨班级数据不可见（行为定义见 `specs/auth-upload/spec.md` 的 R2）
- **操作留痕**：登录、上传、问答各留一条可追溯记录（课纲「审计」要求的最小实现）

## Capabilities

### New Capabilities

- `auth-upload`: 账号口令认证、角色与班级隔离、教学材料上传与索引、操作留痕（审计最小实现）。
- `knowledge-retrieval`: 在本班已索引材料内的检索问答、流式返回、引用回看。

### Modified Capabilities

（无）本仓主规约为空，本 change 全部为新增能力，不修改任何既有要求。

## Non-goals（本版不做）

> **性质**：下表全部为 **【排期】**——「本版范围外，后续版本按需求评估即可做」，**不是永久禁令**。
> 推翻其中任何一条**无需理由**，只须在新 change 的 proposal 里写一句「当时不做的理由为何不再成立」。

| 项 | 性质 | 本版不做，是因为 |
|---|---|---|
| 课堂疑问收集（提交 → 教师查看 → 匿名展示 / 相似合并 / 统一答疑） | 排期 | 业务模块一律后置；先把底座跑通 |
| 个人学习路径与复习提醒 | 排期 | 依赖疑问与掌握数据先积累 |
| 教学反馈看板 | 排期 | 依赖疑问数据先积累 |
| 前沿检索（交叉编码器重排、查询改写 / agentic RAG） | 排期 | 先保证基础检索链路端到端跑通 |
| MCP 工具层与工具级运行时授权 | 排期 | 依赖业务链路先成立 |
| 可观测（链路追踪）与评测集 | 排期 | 有稳定链路后才谈得上度量 |
| 异步任务队列 | 排期 | 课纲有要求，但依赖业务闭环先成立 |

**本版没有任何【有意不做】项。**

## Impact

- **代码区域**：本仓从零建立前端、后端、部署骨架（文件清单见 `tasks.md`）
- **数据**：新增用户 / 班级 / 教学材料 / 切片 / 会话 等表（建表决议见 `design.md`）
- **对外契约**：登录、材料上传、检索问答（含引用）三类接口（可判定契约见 spec delta）
- **配置**：数据库、检索库、模型网关的地址与密钥一律外置为环境变量
