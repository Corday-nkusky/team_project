# Design: 修复镜像版本烟雾检查

## 决策

1. **烟雾检查只验证版本**：该 job 的目标是确认构建参数进入运行二进制，而非验证真实依赖链路。复用服务已有的 `REQUIRE_DEPS=false` 开发模式，避免为一次版本断言增加两个服务容器。
2. **降级不等于成功就绪**：无依赖时 `/health` 返回 503 与依赖错误详情是预期；检查只断言响应为合法 JSON 且 `version` 等于 `GITHUB_SHA`，不把它记作 200 全依赖就绪。
3. **先留日志再清理**：验证步骤失败后，独立 `failure()` 步骤执行 `docker logs`，随后既有 `always()` 步骤删除容器，避免只有空 JSON 解析异常而看不到启动原因。

## 失败路径

| 情况 | 行为 |
| --- | --- |
| 容器启动或监听失败 | 健康响应无法解析，版本断言失败，并输出容器日志 |
| 注入版本不一致 | Python 断言输出实际值与期望值，job 非零退出 |
| MySQL/Qdrant 不可用 | smoke 返回 503 降级响应，版本检查仍可完成；其他完整链路检查不受影响 |

## 兼容性

只修改 GitHub Actions 的 smoke 容器环境与诊断步骤。生产镜像入口、配置默认值、Compose 的 `REQUIRE_DEPS=true` 和 `/health` 契约均不变。
