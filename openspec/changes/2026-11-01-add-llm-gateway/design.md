# Design

## Context

`internal/llm` 已实现 OpenAI 兼容的两种调用：`ChatStream` 向 `{base}/chat/completions` 发送 `stream=true` 并读取 SSE，`Embed` 向 `{base}/embeddings` 批量提交文本。`qa.Index` 在启用网关时生成切片、调用嵌入、确保 Qdrant 集合、删除旧向量并写入新向量；任一步失败都会让材料进入 `failed`。当前缺的是把这些事实写成可验收的契约，并修正启用时仍依赖模型名默认值的配置。

本 change 不新增适配器，也不拆分网关；只把一个「同时支持对话与嵌入」的兼容网关接成可配置、可观测、可复验的正式能力。

## 配置矩阵

| `LLM_API_KEY` | 其余三项 | 行为 |
| --- | --- | --- |
| 空 | 忽略 | 抽取式降级；不要求 base、模型名 |
| 非空 | `LLM_API_BASE` 为 http(s) 绝对地址，`LLM_CHAT_MODEL` 与 `LLM_EMBED_MODEL` 非空 | 启动并启用模型与向量路 |
| 非空 | 任一项缺失或非法 | 监听端口前非零退出，日志只报键名 |

模型名不再有内置默认值。这样 `/health` 显示的模型就是实际调用的模型，避免“配置里没写、代码里静默换成 DeepSeek 默认值”。

## API 契约

`GET /health` 保持免认证与既有字段，只增加 `llm` 对象：

```json
{
  "status": "ok",
  "version": "dev",
  "time": "2026-11-01T00:00:00Z",
  "deps": {"mysql": "ok", "qdrant": "ok"},
  "llm": {
    "enabled": true,
    "chat_model": "course-chat",
    "embed_model": "course-embedding"
  }
}
```

`enabled=false` 时只返回 `{"enabled": false}`。响应不包含 `LLM_API_KEY`、`LLM_API_BASE`、连接串或任何密钥形态的字符串；模型名属于公开的部署元数据，可以返回。

## 调用与索引流程

1. 启用后，对话请求为 `POST {base}/chat/completions`，body 含 `model=LLM_CHAT_MODEL`、`stream=true`、system/user 两条消息；读取 `data:` 行直到 `[DONE]`。网关可能先返回 `reasoning_content`，客户端只消费 `delta.content`，不得把推理内容当回答。
2. 嵌入请求为 `POST {base}/embeddings`，body 含 `model=LLM_EMBED_MODEL`；该材料全部切片按固定条数分批提交，相同切片只嵌入一次再按原位置展开。任一批失败即整体失败，返回数量与提交条数不一致也算失败。
3. 向量维度取响应中第一条向量的实际长度，后续批次必须一致。集合不存在时按该维度创建；集合已存在时先核对维度，不一致立即失败，不删除该材料的旧向量，也不写入新向量。
4. 材料的 `index_status` 只在切片落库、嵌入成功、旧向量删除与新向量写入全部完成后变为 `ready`。任一步失败返回错误，由上传/重索引 handler 标记 `failed` 并写入 `index_error`。
5. 换嵌入模型或维度后，必须删除旧集合并重索引全部材料；系统不自动混用不同维度的向量，也不把维度冲突静默降级为“仅关键词成功”。

## 实现选择

### D1 沿用单一 base/key

当前网关的对话与嵌入端点同源同密钥，单一配置已经够用。拆分网关会引入两套凭据、两套健康与部分能力失败语义，超出本次范围。

### D2 模型名显式必填，不做默认值

默认值是“静默换模型”的来源，且 DeepSeek/OpenAI 的默认模型在第三方网关未必存在。让配置缺失在启动期失败，比让第一次上传变成 `failed` 更容易定位。

### D3 健康信息只暴露模型名

运维需要确认当前调用的模型；模型名不是密钥。base 可能是内网地址，key 是密钥，两者都不返回。`/health` 不做网关网络探活，避免健康检查因外部模型波动而 503；模型可用性由问答流与索引结果体现。

### D4 维度以响应为准，不新增 `LLM_EMBED_DIM`

Qdrant 客户端按第一条向量长度建集合，能避免“配置维度与模型实际维度不一致”的第二处真相源。集合已存在时先读取其维度并在删除旧向量前比较；不一致就失败，避免换模型后先清掉可用旧索引。代价是换模型后必须重建集合；这一操作写入 README 与验收步骤，而不是自动执行数据删除。

### D5 嵌入与向量写入分批，重复切片只嵌入一次

17 MiB 上限意味着切片数可达上万；一次性提交全部文本或一次性 upsert 全部向量会把请求体推到百 MB 级，先被网关或 Qdrant 拒收，再被客户端超时掩盖成“服务不可用”。因此嵌入按 32 条一批、向量写入按 128 点一批；任一批失败即整体失败，材料仍走 `failed` 路径。相同切片去重只影响计算量，不改变切片与向量的一一对应关系。批量参数是实现常量，不新增配置项，避免把容量问题转嫁给部署方。

## 失败路径

- key 为空：降级启动，问答走抽取式；不调用网关。
- key 非空但 base/模型名缺失：启动失败，日志只报键名。
- 对话首字前 5xx/拒连：沿用 R6.5，发送 `degraded` 后用抽取式回答完成。
- 对话中断或空流：沿用 R6.4，以 `error` 结束且不落库。
- 嵌入失败：索引失败，材料 `failed` 且 `index_error` 含原因；恢复后重索引。
- 向量写入失败或维度不符：索引失败，不把材料标成 `ready`，不静默退回仅关键词。
- `/health` 不因模型网关不可达而 503；只报告配置是否启用与模型名。

## 验证策略

- 单元测试：配置矩阵（缺 base、缺 chat 模型、缺 embed 模型、空 key 成功）；`/health` 启用时返回两个模型名且不泄漏 key/base；嵌入分批与去重、批次失败即整体失败、维度漂移拒绝；Qdrant 集合维度不一致时在写入前失败。
- 客户端集成测试（build tag `llm_integration`）：用真实网关验证 `/embeddings` 返回非空向量与 `/chat/completions` 的 SSE 能读到 `[DONE]`；未配置 key 时跳过。
- 本地全链路：启用本地栈，上传含独有词的材料，轮询到 `ready`；从 backend 容器请求 Qdrant 确认该材料有向量点；学生提问，断言 SSE 有增量、`done`、引用标题与材料一致，且无 `no_evidence`/`degraded`。
- 失败演练：把嵌入模型临时改为不存在值，重启后上传应得到 `failed` 与 `index_error`；恢复配置并重索引后转 `ready`。
- 回归：OpenSpec 严格校验、`quality-gate.mjs` 与两套 e2e 保持全绿。浏览器 e2e 在启用真实网关的本地栈上运行，问答与引用断言依赖模型返回 `[n]`；键盘引用断言使用即时 mock 流，因为本机 headless Chrome 在真实长 SSE 结束后不再向页面派发 CDP 按键，真实长流路径继续覆盖引用内容与鼠标聚焦。
