# Design: 完成第 11 课最终验收证据链

## 决策

1. **门禁固定为同一入口**：`make check` 继续负责分层、密钥、格式、构建、vet、单测与安全反例；`make check-security` 负责密钥和 Go/npm 可达漏洞。Windows 的 `scripts/make-check.mjs` 与 Makefile 调用同一脚本，CI 不另写一套判据。
2. **依赖审计失败必须可见**：govulncheck 或 npm audit 返回非零即门禁失败；报告保留原始输出。修复优先升级工具链与直接依赖，不用忽略清单绕过。
3. **审计仍只增不改**：`audit_logs` 采用 additive migration 增加 `skill_name`、`usage_count`、`duration_ms`、`object_type`、`object_id`；查询必须带 `class_id`，教师可读，学生 403。明细只允许分类与长度受限文本，不存令牌、口令或完整材料。
4. **观测直接来自真实记录**：技能调用量与错误率取审计/MCP 记录，P95 取服务端请求时延，队列深度取 `index_tasks`。不另接第三方分析服务。页面只显示本班聚合数据。
5. **告警可重复演示**：脚本读取真实观测接口，在持续条件满足时向本地通知接收器发送 JSON，接收器把送达时间写入 `reports/`；失败制造使用随机测试数据，不改历史证据。
6. **缓存键必须包含班级**：材料列表缓存只存在进程内，TTL 2 秒；上传、重索引与索引状态变更使对应班级版本递增。缓存不跨班、不缓存错误，测试覆盖写后可见与跨班隔离。
7. **压测只改一个变量**：沿用 `scripts/bench.mjs` 与既有并发、请求数，先保存改进前结果，再启用缓存复测；报告同时给吞吐、P95 与错误数，不挑选单次最好值。
8. **提示词版本可追踪**：基础提示词以名称+版本登记，问答 SSE `meta` 返回实际版本；技能自身继续使用数据库递增版本。版本变更只增记录，不改历史。
9. **最终证据诚实**：报告只引用已执行命令和已生成文件。无公网、真实用户、网盘账户或同伴评审的事项不写成完成。

## 失败路径

| 情况 | 行为 |
| --- | --- |
| 依赖审计存在高危 | `check-security` 非零，CI 失败 |
| 学生读取审计或观测 | 403，不返回本班聚合数据 |
| 审计/观测数据库查询失败 | 500 统一错误体，不伪装为空数据 |
| 队列或指标暂无样本 | 返回空序列与 `null` P95，页面显示空态 |
| 告警未达到持续条件 | 不发送通知，脚本明确输出未触发 |
| 告警通知接收器不可达 | 非零退出，不写“已送达” |
| 材料写入后缓存未失效 | 单测失败，禁止合入 |
| 压测出现错误响应或断流 | 压测非零，两轮结果均不得标绿 |
| 干净启动缺配置或依赖失败 | 启动脚本非零，记录原始输出 |

## 兼容性

- 所有数据库变更只增列/增索引/增记录，可重复启动。
- 新接口均置于现有 Bearer 认证和班级隔离之后，不改变旧响应字段。
- 材料缓存只缩短重复查询的数据库负载，TTL 与写后失效保证可观察一致性。
- 观测与报告不记录完整问答、材料正文、请求体或敏感配置。
