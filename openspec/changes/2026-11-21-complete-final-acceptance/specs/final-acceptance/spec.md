# final-acceptance Specification

## Purpose

把第 8～11 课剩余验收项转成可执行门禁、可查询运行数据和可复跑证据，保证最终报告中的结论均可复核。

## ADDED Requirements

### Requirement: F1 安全与 CI 门禁

系统 SHALL 通过 `make check` 与 `make check-security` 执行功能和安全检查，依赖存在高危时安全门禁 SHALL 非零退出。CI SHALL 并列执行两个检查并构建带提交版本的运行镜像。

#### Scenario: F1.1 安全门禁全绿

- **GIVEN** Go/npm 依赖已升级到无已知高危且密钥扫描无命中
- **WHEN** 执行 `make check-security` 或其 Node 等价入口
- **THEN** 密钥扫描、govulncheck、npm audit 与安全单测全部执行且退出码为 0

#### Scenario: F1.2 依赖高危阻断

- **GIVEN** 任一受支持依赖审计返回高危或严重漏洞
- **WHEN** 执行安全门禁
- **THEN** 命令非零退出且输出对应审计工具摘要，不得只写“已登记”后继续判绿

#### Scenario: F1.3 安全反例常驻

- **GIVEN** SQL 注入、XSS、CSRF/无 Cookie 等价反例已进入常驻用例
- **WHEN** 执行功能门禁和接口测试
- **THEN** 三类反例均有内容与权限断言，失败时任一命令非零退出

### Requirement: F2 七列审计与权限

系统 SHALL 记录操作人、时间、类型、对象、结果、技能标识、用量与耗时，并提供仅本班教师可读的查询接口；被拒绝的写操作 SHALL 同样留痕。

#### Scenario: F2.1 技能调用可回查

- **GIVEN** 本班一次启用技能的问答已完成
- **WHEN** 教师按技能名称查询审计记录
- **THEN** 返回记录包含七列且技能名、结果和耗时与本次调用一致

#### Scenario: F2.2 学生查询与越权写入

- **GIVEN** 学生具有有效令牌
- **WHEN** 查询审计或尝试修改技能
- **THEN** 查询返回 403，修改返回 403 且数据不变，修改拒绝记录可按操作人和时间窗查到

#### Scenario: F2.3 跨班与查询故障

- **GIVEN** 两个班均有审计记录，或数据库查询失败
- **WHEN** 教师查询审计列表
- **THEN** 正常时只返回本班记录；故障时返回 500 统一错误体而不是空列表

### Requirement: F3 运行观测与告警

系统 SHALL 提供本班技能调用量、每技能错误率、接口 P95 和任务队列深度，并在教师页面显示三类图；告警 SHALL 支持持续条件判定和可验证通知。

#### Scenario: F3.1 三类图使用真实数据

- **GIVEN** 本班存在技能调用、接口请求和异步任务
- **WHEN** 教师打开运行观测页
- **THEN** 页面展示技能调用量、错误率、P95 与队列深度，数据来自查询接口而非硬编码

#### Scenario: F3.2 告警真实触发与送达

- **GIVEN** 告警规则为错误率持续超过阈值且本地通知接收器已启动
- **WHEN** 用随机测试数据使错误率连续满足条件并执行告警检查
- **THEN** 接收器记录观察量、持续条件、动作、面板地址和送达时间，脚本退出码为 0

#### Scenario: F3.3 未达条件与通知失败

- **GIVEN** 指标未持续越限，或通知接收器不可达
- **WHEN** 执行告警检查
- **THEN** 未越限时不发送通知；不可达时非零退出且不产生“已送达”记录

### Requirement: F4 材料查询改进与复测

系统 SHALL 对材料列表增加按班隔离且写后失效的短 TTL 缓存，并用同一压测脚本和参数比较改进前后结果。

#### Scenario: F4.1 缓存不破坏一致性

- **GIVEN** 两个班均有材料且一班列表已被缓存
- **WHEN** 另一班查询列表，或一班上传/重索引后再次查询
- **THEN** 另一班不得读到缓存内容，一班写后结果反映最新状态

#### Scenario: F4.2 同参数两轮压测

- **GIVEN** 改进前基线和改进后代码使用相同服务配置、脚本与参数
- **WHEN** 分别执行提交、查询、检索压测
- **THEN** `reports/bench.md` 记录两轮吞吐、P95、错误数、饱和点与改进提交标识，查询接口改进可观察

#### Scenario: F4.3 压测失败不得标绿

- **GIVEN** 任一轮出现 HTTP 错误、SSE error 或提前断流
- **WHEN** 压测结束
- **THEN** 脚本非零退出且报告保留失败，不选择性删除失败样本

### Requirement: F5 可复现交付与提示词版本

系统 SHALL 登记实际基础提示词版本，在问答元数据中返回该版本，并支持从干净目录按 README 一条命令启动；最终报告 SHALL 只引用真实证据。

#### Scenario: F5.1 提示词版本可追踪

- **GIVEN** 基础提示词已以名称和版本登记
- **WHEN** 学生完成一次问答
- **THEN** SSE `meta` 含实际 `prompt_version`，技能记录仍有独立递增版本

#### Scenario: F5.2 干净启动

- **GIVEN** 新目录不含本机 `.env`、旧容器和旧数据卷
- **WHEN** 按 README 执行唯一启动命令
- **THEN** 脚本生成随机配置、全部服务就绪且 `/health` 返回 200 与依赖状态

#### Scenario: F5.3 证据缺失不得冒充完成

- **GIVEN** 公网、真实用户、网盘或同伴评审任一项没有真实结果
- **WHEN** 写最终报告
- **THEN** 对应项明确标为未完成及原因，不出现空链接、“已通过”或代签
