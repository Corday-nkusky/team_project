# Proposal

## Why

CampusClaw 的核心业务链路已经通过真实接口与浏览器验收，但界面仍是默认表单和卡片的组合：品牌与班级上下文弱、提问和引用缺少工作台层次、教师上传与材料列表挤在单列中、登录页没有清晰的产品价值表达。功能可用，却不能让学生和教师迅速建立“我在这里做什么、答案为什么可信、下一步去哪”的判断。

价值三问：

- **谁的问题**：首次登录的课堂用户、需要频繁提问的学生、上传并核对材料的教师，以及在窄屏上演示或使用的成员。
- **不做会怎样**：用户需要自行从朴素控件中推断信息架构；回答、引用与异常状态不够醒目；桌面空间利用率低，移动端导航与长表单体验弱，核心能力即使正确也显得不完整。
- **做完如何验证**：既有 Go 与浏览器 e2e 全部保持通过；新增视觉与可访问性检查覆盖登录、教师/学生工作台、流式回答、引用、上传、四态、键盘焦点、320–1440px 布局；生产构建成功且无控制台错误。

## What Changes

1. 建立统一视觉系统：深青色品牌侧栏、暖色行动按钮、明确的字体层级、间距、圆角、阴影、焦点与状态色；不引入运行时 UI 依赖。
2. 重构应用外壳：桌面侧栏与移动导航共享同一组入口，持续展示班级、角色、用户和退出动作；保持 `ask / materials` 两页范围。
3. 重做登录页：产品价值、材料依据承诺、登录表单和演示账号形成清晰分区；保留统一登录失败文案和忙碌状态。
4. 重做提问工作台：突出大问题输入区、提交/停止动作、生成状态、回答正文和可回看引用；引用标记与来源支持键盘操作。
5. 重做材料工作台：教师上传与本班材料形成响应式双栏，学生仅查看；保留标题计数、文本/文件上传、重索引、加载/空/错误/正常四态。
6. 完善响应式与可访问性：语义区域、焦点可见、状态通知、减少动态效果偏好、长标题与 320px 窄屏不溢出。

## Capabilities

### New Capabilities

- `learning-workspace`：定义统一应用外壳、登录体验、提问与引用工作台、材料管理工作台及响应式/可访问性要求。

### Modified Capabilities

（无；既有认证、上传、检索、SSE 与错误契约不变。）

## Non-goals（本次不做）

| 项 | 原因 |
| --- | --- |
| 新增问答历史、多轮对话、材料详情/删除 | 属于新产品能力与后端路由，超出界面优化范围 |
| 引入 Markdown/HTML 渲染 | 会增加 XSS 与依赖审计面，保持纯文本回答 |
| 引入大型 UI、图标或字体依赖 | 当前需求可用 CSS 与内联 SVG 完成，避免无谓包体和供应链成本 |
| 修改 API、数据库、鉴权、检索与提示词 | 本变更只重构展示与交互，既有业务契约必须原样保留 |
| 为视觉效果删除或放宽现有 e2e 断言 | 所有既有断言继续作为回归基线 |

## Impact

- `frontend/src/App.tsx`、`pages/LoginPage.tsx`、`pages/AskPage.tsx`、`pages/MaterialsPage.tsx`、`styles.css`。
- 可新增纯展示用图标组件；`api.ts` 与后端接口不变。
- `scripts/e2e-ui.mjs` 继续验证既有行为，可补充新布局/可访问性断言，但不弱化原断言。
- 验收命令：`npm run build`、`node scripts/quality-gate.mjs --with-spec --with-e2e`、`node scripts/e2e-ui.mjs`，以及真实浏览器桌面/窄屏检查。
