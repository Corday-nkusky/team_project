# 七维度评审表（本组 AI 生成代码）

> **依据**：课程《小组项目下一阶段重点 · 学会审核 AI 写的代码》第二层原文。七个维度为：需求覆盖率 / 与需求的一致性 / 失败路径覆盖 / 查询性能风险 / 重复代码比例 / 漏洞风险 / 高风险场景。
> **三分法**（原文）：可用＝逻辑正确、符合规约与安全要求，补测试后交同学评审；待修改＝方向对但有缺陷或偏离需求，列出修改项改完重审；风险＝存在越权、数据错乱等风险或与需求无关，直接丢弃重写。
> **配套记录**：`reports/review-01.md`（安全自查）、`reports/review-02.md`（技能与 MCP 新增代码）、`reports/review-03.md`（门禁与交付链路）。
> **手段**：`AI`＝AI 自审逐段读；`门`＝脚本门禁；`单`＝Go 单测；`规`＝OpenSpec 场景对照；`人`＝人工确认。
