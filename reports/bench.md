# 压测报告（第 10 课：吞吐与 P95 随并发变化）

> 实测 2026-11-17 晚，五服务由 `node scripts/up.mjs` 起（MySQL / Qdrant / backend / worker / mcp-server）。
> 事实分级：【实测】本机真实请求 /【推断】依据实测数字的归因 /【未验证】没有数字的部分。
> 脚本：`scripts/bench.mjs`，参数走环境变量，原始结果 `reports/bench-raw.json`，控制台输出 `reports/bench-run.log`、`reports/bench-fast.log`。

---

## 1. 方法

```bash
BASE_URL=http://127.0.0.1:8080 LEVELS=1,4,8 REQUESTS=8 \
  OUT=reports/bench-raw.json node scripts/bench.mjs
```

| 项 | 值 |
| --- | --- |
| 接口 | 提交 `POST /api/materials`、查询 `GET /api/materials`、检索 `POST /api/ask` |
| 并发级别 | 1 / 4 / 8 |
| 每级请求数 | 8（每接口每级，合计 72 次） |
| 提交内容 | 固定标题与正文，靠唯一约束复用同一任务，不产生成批材料 |
| 检索内容 | 「酶是什么？请依据本班材料回答。」走真实 SSE，读到流结束才计时 |
| 模型 | 网关启用，`chat_model=glm-5.3-flash`，`embed_model=embedding-3` |
| 吞吐定义 | `请求数 / 墙钟秒数`（并发请求的实际完成速率，不是延迟之和的倒数） |

## 3. 饱和点【实测 + 推断】

- **提交**：吞吐从 133 涨到 419 req/s（C=1→4），再到 433（C=4→8）几乎不再增长；P95 从 8ms 升到 16ms。**饱和点约在并发 4～8 之间**。
- **查询**：吞吐在 C=4 达峰 1969 req/s，C=8 回落到 1866；P95 始终 ≤ 3ms。**饱和点在 C=4 附近**。
- **检索**：并发 1→8 吞吐从 0.03 升到 0.23 req/s，但 P95 在 24～64 秒量级；C=4 的 P95 最差（64s），C=8 反而降到 27s。样本只有每级 8 次，**不足以把 C=8 的下降归因成某个具体机制**，只能说"没有随并发单调恶化"。

## 4. 瓶颈归因

- 【实测】应用自己的两个接口在 C≤8 时 P95 ≤ 16ms，不是瓶颈。
- 【实测】检索接口的墙钟耗时与模型生成量同量级（单次 16～64 秒），且回答为 74 个 SSE delta / 133 字（见 `reports/verify-llm.log`）。
- 【推断】检索瓶颈在**外部模型网关的生成延迟**，不在 Go 服务、MySQL 或 Qdrant；要提速应减少生成token、换更低延迟模型或对高频问题做缓存，而不是继续加应用侧并发。
- 【未验证】未测网络抖动、模型网关限流（429）下的行为；未测同时混合三类接口的场景。

## 本篇没能验证的部分

- 改进后第二轮数字——未做，见第 5 节。
- 更高并发（16 / 32）与更长时长；每级只有 8 次请求，P95 的统计置信度有限。
- 混合负载与真实用户分布；三接口是分开压的。
- 模型网关限流、超时、断连时的吞吐退化。
- `reports/bench-raw.json` 里 `wall_seconds` 只保留两位小数；提交/查询的吞吐以脚本按未舍入墙钟时间输出的 `throughput_rps` 为准，检索的吞吐用几十秒量级的 `wall_seconds` 重算（见文件内 `note` 字段）。

## 问答流验收与计时（2026-11-19）

`ask` 结果中的 `answered` 统计含引用清单、可见正文且收到 done 的回答；`no_evidence` 统计空引用、约定拒答文案并收到 done 的请求。已完成的抽取式降级回答同样计入 answered。HTTP 失败、error 事件、提前断流、正文或必要引用缺失均计入 errors，使压测退出码为 1。

`first_text_p50_ms / first_text_p95_ms` 从请求开始计到首个可见正文增量；`done_p50_ms / done_p95_ms` 计到收到 done。两组均只统计正常完成的样本，无样本写 null。原有 p50_ms / p95_ms 继续覆盖整次请求（含失败），提交和列表接口的统计口径沿用原定义。

受控回归：`node --test scripts/bench-ask-stream.test.mjs`。本地单次复跑可执行 `BASE_URL=http://127.0.0.1:8081 ENDPOINTS=ask LEVELS=1 REQUESTS=1 OUT=/tmp/ask-smoke.json node scripts/bench.mjs`，按部署调整端口。此次实测正常拒答 1、错误 0，首字与 done 均为 3795 ms，整次请求 3802 ms。该记录仅验证采集链路；上文历史基线仍采用原口径。
