# 安全开发规范

适用范围：认证、授权、输入处理、密钥、日志与依赖。

## 规则

1. **口令**：只存 bcrypt 哈希；任何响应、日志、审计不得出现明文口令或哈希。
2. **令牌**：access token 无状态短期有效；refresh token 只存 SHA-256 摘要，轮换即失效；登出作废 refresh。
3. **越权默认拒绝**：所有资源访问先判班级，再判角色；跨班返回 403/404，且响应体不泄漏目标是否存在。
4. **失败同形**：登录失败不区分「账号不存在」与「口令错误」。
5. **输入边界**：请求体 1 MiB 上限（上传 32 MiB 上限）；只接受声明的内容类型；PDF 仅抽取文本。
6. **日志脱敏**：不记录 `Authorization`、请求体、查询串、令牌、口令；`/health` 不含密钥与连接串。
7. **密钥卫生**：代码与 compose 不保留可用默认密钥；`.env` 不入库；示例值必须让服务拒绝启动。
8. **注入防护**：材料文本只作为「数据」拼入提示词，必须明确指示模型忽略其中的指令；不得把材料当作系统指令。
9. **依赖**：新增第三方库需在 PR 说明用途与许可证；已知高危漏洞未修复不得合并。
10. **上传留痕**：上传、登录、问答写审计；失败动作记录原因类别，不记录敏感值。

## 检查方式

- `node scripts/check-secrets.mjs`（真实密钥形态、默认密钥、`.env` 入库）
- `go test ./internal/config`（示例/短密钥拒绝）
- e2e：R1.2 失败同形、R1.3 篡改令牌、R2.1/R2.2 跨班、R9.5 健康检查不泄漏
- 评审清单：权限矩阵是否随新接口更新

## 违规处理

- 密钥泄漏：立即轮换、吊销相关令牌、回滚提交，24 小时内补事故记录。
- 越权或数据泄漏：按 P0 处理，先止血再修复，并补对应负向 e2e。
- 其他违规：门禁失败阻断合并；评审发现的问题在合入前修复。

## 有效性验证

每学期做一次演练：在测试分支写入一个假 `sk-` 密钥并给 compose 加 `:-` 回落，确认 `check-secrets.mjs` 同时报出两项；结果记入验收文档。
