# 部署运维规范

适用范围：`deploy/`、镜像构建、启动脚本、健康检查与回滚。

## 规则

1. **一条命令**：新环境从零到可访问 `node scripts/up.mjs` 完成；手动步骤不得超过三步。
2. **配置必填**：compose 对 `JWT_SECRET`、MySQL 口令使用 `${VAR:?}`，不得提供 `:-` 回落默认值。
3. **健康检查**：免认证 `GET /health`；依赖全通 200，任一失败 503；响应含 `version`、`time`、`deps`，不含密钥。
4. **版本可追溯**：镜像构建注入 `VERSION`，`/health` 与启动日志可见；发布打 tag（骨架为 `v0.0.1-skeleton`）。
5. **日志到 stdout**：容器不写本地日志文件；由编排层收集，单行 JSON。
6. **镜像最小化**：多阶段构建，运行镜像不含编译工具链与 Node；以非 root 用户运行。
7. **回滚即换版本**：回滚 = 部署上一个 tag；数据库迁移必须向前兼容，禁止依赖回滚脚本。
8. **依赖顺序**：MySQL 健康后再启动后端；Qdrant 启动较慢时由后端启动重试承担。
9. **端口冲突**：MySQL 映射 13306 以避开宿主机 3306；对外仅暴露 8080。

## 检查方式

- `node scripts/up.mjs` 后 `curl -s localhost:8080/health` 返回 200 且 `deps` 全 ok
- `docker compose config` 检查无默认密钥
- e2e 首项断言 `/health`
- `docs/lesson-07/verification.md` 记录版本与时间

## 违规处理

- 缺必填校验或默认密钥：视为发布阻断项，立即修复。
- 健康检查误报（依赖坏了仍 200）：P0，修复前禁止发布。
- 回滚失败：暂停发布，补齐可回滚方案后再继续。

## 有效性验证

在全新目录克隆仓库，只执行 `node scripts/up.mjs`，确认 `/health` 200；随后停掉 Qdrant，确认 `/health` 变 503。结果记入验收文档。
