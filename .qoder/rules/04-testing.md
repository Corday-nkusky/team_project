# 测试规范

适用范围：单元测试、接口 e2e、浏览器 e2e 与验收脚本。

## 规则

1. **场景映射**：每个 Scenario 至少一条自动化断言；e2e 输出中标注对应编号（如「R5.2 未命中」）。
2. **负向不少于正向的一半**：权限、空输入、依赖不可用必须有独立用例。
3. **真实依赖优先**：e2e 直连真实 MySQL / Qdrant / HTTP，不用 mock 替代待验证的边界；纯逻辑用单元测试。
4. **退出码即判定**：验收脚本全绿退出 0，任一失败退出 1；禁止靠人工读日志判断。
5. **数据隔离**：每次运行生成随机独有词；用例不依赖执行顺序与历史数据。
6. **可复现**：测试命令、环境变量、依赖版本写入 README 与 tasks 的「实测」。
7. **不测实现细节**：断言面向可观察行为（状态码、响应字段、流式事件），不断言私有函数。
8. **失败信息可诊断**：断言失败时输出实际值与期望值。

## 检查方式

- `node scripts/quality-gate.mjs`（单元测试）
- `node scripts/quality-gate.mjs --with-e2e`（Go 接口 e2e）
- `node scripts/e2e-ui.mjs`（浏览器 e2e，需前端与后端已启动）

## 违规处理

- 无断言的「测试」视为未测试；评审直接打回。
- 为过门禁而弱化断言：回滚该测试并补足；在评审记录中注明。
- 偶发失败：必须定位根因，禁止加重试掩盖。

## 有效性验证

故意把某条断言改成必失败（如期望 999），确认 e2e 以退出码 1 结束，然后还原；记录在验收文档。
