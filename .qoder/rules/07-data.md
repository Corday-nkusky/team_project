# 数据规范

适用范围：MySQL 表结构、索引状态、切片数据与审计记录。

## 规则

1. **迁移向前兼容**：只增列/增表/加索引；删列、改类型必须拆成「停用 → 迁移 → 清理」三步，且每步可独立回滚。
2. **幂等迁移**： `Migrate` / `Seed` 可重复执行；以唯一键保证种子不重复。
3. **索引状态机**：材料切片状态只有 `pending → ready` 与 `pending → failed`；`failed` 必须带 `index_error`，可由重索引接口转 `ready`。
4. **原文与切片分离**：原文落库不可变；切片可重建，重建不得改变材料 id 与班级归属。
5. **审计只增不改**：审计表只允许 INSERT；不得 UPDATE/DELETE；失败动作记录原因类别，不记录敏感值。
6. **班级归属不可变**：材料的 `class_id` 创建后不得修改；需要换班时新建材料。
7. **时间统一**：库里存 UTC 或统一时区，接口输出 RFC3339；禁止混用本地时间字符串。
8. **备份**：发布前对 MySQL 卷做快照；恢复演练每学期一次。

## 检查方式

- 迁移评审：对照本规范逐条检查 SQL
- e2e：上传后 `index_status=ready`；Qdrant 不可用时 `failed` 且可重索引
- 审计：三类动作各一条记录；登录失败留痕且无明文口令
- `SHOW CREATE TABLE` 抽查唯一键与索引

## 违规处理

- 破坏性迁移：阻断合并；已执行则按备份恢复并补评审。
- 审计被改写：视为合规事故，立即排查并保留证据。
- 切片与原文不一致：标记材料 `failed`，重索引；不得手工改库掩盖。

## 有效性验证

在测试库执行一次「Qdrant 停机 → 上传 → 重索引」流程，确认状态从 `failed` 正确转为 `ready`，切片数与原文长度匹配；记录在验收文档。
