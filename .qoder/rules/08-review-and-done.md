# 评审与完成定义

适用范围：所有合并请求与阶段交付。

## 完成定义（DoD）

一项工作只有同时满足以下条件才算完成：

1. 对应 OpenSpec change 已写、Scenario 含 GIVEN/WHEN/THEN、失败路径齐全。
2. 代码实现与 spec 一致；tasks 每条勾选并写「实测」。
3. `node scripts/quality-gate.mjs` 全绿；涉及接口的改动附 e2e 结果。
4. 文档同步：README、AGENTS.md、相关规范或验收记录已更新。
5. 另一位成员完成评审并在 `docs/lesson-07/peer-review.md` 签字。

## 评审清单

- [ ] 需求可追溯到 Requirement 编号
- [ ] 新接口有鉴权、班级隔离、审计（如适用）
- [ ] 新配置项已加入 `.env.example` 与验收文档
- [ ] 负向用例覆盖拒绝/越权/依赖失败
- [ ] 日志与响应无敏感值
- [ ] 迁移向前兼容
- [ ] 文案与 spec 完全一致
- [ ] 没有为过门禁而弱化断言

## 规则

1. **作者不能评审自己的变更**；自审只能作为提交前检查。
2. 评审意见必须落到具体文件或行为；不接受「看起来没问题」。
3. 评审通过后由作者合并；合并前门禁必须为绿。
4. 评审记录写入 `docs/lesson-07/peer-review.md`（评审人、日期、结论、遗留项）。

## 违规处理

- 未经评审直接合并：回补评审；连续两次则在站会说明并暂停合并权限。
- 代签或伪造评审记录：视为学术诚信问题，按课程规定处理。

## 有效性验证

抽查最近三次合并：均应有对应 change、门禁记录与评审签字；缺一项即判定流程失效并整改。
